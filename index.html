Security is a system property. KeyPointJS offers building blocks; your configuration and deployment still matter.

Read security guidance →
✓

Expiration and identity checks

Reject missing, unknown, or expired keypoints in the request validator.

Explicit scope decisions

!

Know your configuration

Secret headers are optional today; empty origin allowlists allow any origin. Review the current behavior.

!

Verify enforcement boundaries

Per-keypoint allowed IPs are not enforced by the validator. Read the security notes before deployment.

A SMALL, REAL EXAMPLE

Start with a
protected route.

Install from npm, issue an identity, then check permission where the resource is served.

Build your first API →
server.js
import { KeypointJS } from 'keypointjs';

const api = new KeypointJS();

await api.createKeypoint({
  keyId: 'client-a',
  scopes: ['orders:read'],
  protocols: ['https']
});

api.get('/orders', (ctx) => {
  if (!ctx.hasScope('orders:read')) {
    return ctx.status(403);
  }
  return ctx.json({ orders: [] });
});

await api.listen(3000, '127.0.0.1');
